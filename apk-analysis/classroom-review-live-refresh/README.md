# 讨论笔迹自动刷新与取消本地两张照片限制

贡献者：xuezhangjam、Codex。自有新增代码／窄补丁 GPL-3.0-only；原应用及 SDK 的许可不因此改变。

基于已修复回顾进入闪退的 3.2.2.0 修改版：输入 SHA-256 `f2b93d1a95886bdef42aa9548580db5d9b0a07c9412c90dbed14d05aa877ff79`。包名、版本、SDK、权限和修改版签名保持。成品文件名及 SHA-256 见 `build.json`。

## 本轮变化

- 回顾分组讨论在前台、可见且已加载时，每约 2 秒通过原鉴权历史详情接口读取笔迹，真正合并到当前原生画布。此前主要进入时读一次，后续回读也未持续触发画布更新，因此双方常要重开才能看到变化。
- 使用定时读取，不依赖课后仍有有效 MQTT 订阅。接收方需要使用这版修改客户端并打开对应小组；发送方保留原自动上传。不能使未修改的官方客户端自动刷新，也没有修改老师端 App。
- 远端新增与删除随完整服务器快照更新，本地尚未上传、被拒绝或结果待确认的笔迹继续覆盖合并。读取不会把别人的笔迹重新上传。
- 在原生工具栏已有的触摸处理器前添加一次观测调用，不替换原监听器、不消费事件。落笔、拖动和多指操作期间延后更新，结束后约 180ms 再合并；图形编辑中也不替换画布。保留缩放和平移，重复快照不重画。
- 页面暂停／隐藏时停止发起刷新请求，恢复前台后继续；切组、关闭、账号变化隔离旧响应。同组重叠读取合并，慢请求不堆积，失败逐步延长到最多约 15 秒的间隔。
- 「同步状态」即使没有待传笔迹，也会主动读取刷新。后台观察读取不会把服务端明确拒绝的上传变成每 2 秒自动重传，也不会清掉原上传错误。
- 取消小组讨论 `takePhoto()` 里“本人已有图片数 ≥ 2”的本地计数拦截。直接保留原生拍照／相册入口、监听器、裁剪、上传和业务返回处理，支持继续添加第 3 张及更多照片。没有改服务器校验或伪造上传成功，服务端是否另有限制仍以实际返回为准。
- 本轮自动刷新针对笔迹；没有另写图片元数据自动刷新的流程。

## 验证与边界

`test.py` 执行实际自有 Java：队列测试、原功能回归、自动读取与画布更新的可观察 API 替身测试。覆盖新笔迹／删除、手动刷新、未上传笔迹、触摸及图形编辑、缩放位置、暂停恢复、切组、慢请求、重试退避、账号切换和绘制回调不重复上传。

`verify.py` 核对实际 APK 的规范化 DEX 差异、跨 DEX 引用、无重复类、方法上限、包名／权限、ZIP 与同证书 V2/V3 签名。原生只改变两个方法：触摸处理器增加一个前缀调用；照片入口移除计数限制前缀，其原生入口后半段逐指令保持。另检查照片结果回调的先前闪退修复仍在，新增触摸调用和照片入口没有未初始化寄存器。

`test_photo_limit.py` 在真实原生 DEX 指令上模拟本人图片数 0／1／2／3／10／50／500，搭配他人图片数 0／1／2／7／20，共 35 组：旧包按本人达到 2 张时阻止，新包均进入原拍照页面。此为本地控制流测试，不是相机、相册或真实图片上传验收。

没有执行 Android ART、连接 Pixel、实际双设备互写或访问学校 HTTP/MQTT。自动刷新延迟还取决于上传、网络和服务器历史数据更新，不能凭离线替身测试宣称真实环境已通过。

## 构建

工作区根目录运行：

```powershell
python apk-analysis/classroom-review-live-refresh/test.py
python apk-analysis/classroom-review-live-refresh/build.py
python apk-analysis/classroom-review-live-refresh/verify.py
python apk-analysis/classroom-review-live-refresh/package_source.py
```

本地工具沿用 Java 21 JRE、Apktool 3.0.3、ECJ、Jadx 1.5.6 附带 D8、Android 34 android.jar、uber-apk-signer 及 classroom-mod 签名密钥。精确匹配缓存不存在时，构建从输入 APK 解码 DEX4。检查依赖 Python androguard、loguru。

归档仅含自有代码、编译 API 声明、测试替身、窄补丁和报告；不含 APK、工具、密钥、原厂完整源码或反编译树。构建替换 DEX4、DEX14，其他载荷保持。没有自动发布 GitHub。
