# 讨论结束后图片上传与文档同步偏移修补

贡献者：xuezhangjam、Codex。自有新增代码及窄补丁沿用 GPL-3.0-only；原应用和 SDK 的许可不因此改变。

基线为用户提供的 `学生端课堂-3.2.2.0-讨论自动刷新-多图版.apk`，SHA-256：`3f142320555dc47fd985a03ff1caa2366bcb59e37c55395134555af3548f6c81`。输出名称、摘要及字节数见 `build.json`。包名 `com.hljzjx.edu.student.classroom`、版本 3.2.2.0 / 322000、权限和既有修改版签名保持。

## 图片上传

原结果回调在裁剪返回后仅放行 DISCUSSING / PRESENTING 状态；ENDED 状态即使仍有工具栏，也会在真正调用 `saveImage` 之前返回。本次接入既有“结束后续写”的资格判断，让当前有效小组在结束后继续进入原拍照／相册、裁剪和上传流程。

打开拍照入口时记录当前账号、课堂、讨论及小组；裁剪返回时再次检查。切组、切讨论、切账号或页面失效后返回的旧结果不会上传到新的上下文。课堂回顾仍保留既有 `ReviewDrawing.photoResult` 的有效会话判断。图片上传已开始且仍属于当前有效的结束讨论时，结束回调不会仅因状态改变取消该图片上传。先前两张图片的本地数量限制仍不恢复。

未改上传服务、身份和原上传错误处理，也没有伪造成功。服务端是否接收、保存及向其他客户端展示，仍需真实课堂验证。本次没有增加图片元数据自动轮询；原回顾笔迹自动刷新保持不变。

## 文档缩放和平移

本次只修补课堂文档 SDK 识别为 PDF 的文档类展示，不改变普通 PPT 的公共画布、适配比例及 DOM 修补。

现有手写 SDK 的接收笔迹按 `本地画布宽 / 教师来源宽` 换算，而文档布局消息中的平移量和滚动量直接按接收方像素应用。教师和学生画布宽度不同时，会出现“已同步但偏移”。本次在原同步流程读取消息之后，将 translationX、translationY 和 scrollY 按相同宽度比例换算；scale 保持原值，文档及教师／学生笔迹继续使用同一组目标平移量。延迟恢复和窗口宽度变化从原始消息重新换算，避免重复乘比例。

教师画布尺寸只从教师层的原始笔迹来源字段读取，不改变笔迹数据。文档切换会清除尺寸缓存；自由浏览和本地操作保护仍使用原生状态。PDF 还跳过旧的仅对教师笔迹扣除顶边距的绘制补偿，使同一画布上的文档和笔迹使用共同原点。

**尺寸信息边界：**现有布局消息只带 scale 和平移量，未确认含有发送端视口尺寸。尚未收到当前文档教师笔迹的有效来源尺寸时，本补丁保留原始消息，不猜教师分辨率。因此不能保证所有无笔迹文档也立即消除跨设备偏移；需要真实教师投放文档验证。当前没有读取真实课件资源或 Pixel Tablet。

结论见 `statistics-audit.md`：当前仅确认个人作答统计和课堂排行榜模型，未确认包含全班各选项人数或每位同学选择的可用数据源。本包没有加入假统计入口，也没有访问学校服务验证或获取其他同学数据。

## 验证范围

`verify.py` 检查最终签名 APK，确认只替换 DEX4、新增 DEX15，其余载荷逐字节不变。原生 10 个方法在移除明确的新增调用／分支后与基线逐指令等价；另加两个转发桥接方法，原字段不变。检查跨 DEX 成员引用、方法上限、重复类、包信息、权限、同证书 V2 / V3 签名，以及照片回调等关键分支的寄存器初始化。

`test_behavior.py` 运行实际自有 Java 与可观察 API 替身，覆盖图片会话隔离、取消、结束中上传、回顾旧结果、不同宽度和缩放、负平移、滚动、窗口变化、自由浏览、页面失效、切文档及原始消息不变。包含旧的未换算平移会失败的负对照。结果详见 `behavior-tests.json` 和 `verification.json`。

这些是离线控制流、链接和 Java 行为检查；没有运行 Android ART、Pixel 真机、真实相机、双端 MQTT 或学校上传接口，不能当作实际课堂验收。

## 本地构建

在原工作区根目录执行：

```powershell
python apk-analysis/classroom-discussion-document-fix/build.py
python apk-analysis/classroom-discussion-document-fix/verify.py
python apk-analysis/classroom-discussion-document-fix/package_source.py
```

沿用本地 Java 21、ECJ、Apktool、Android 34 android.jar、Jadx 附带 D8 和 uber-apk-signer；检查依赖 androguard、loguru。签名密钥需要自行提供。精确匹配的基线缓存不存在时会从输入 APK 解码 DEX4。

源码包只含自有 Java、编译声明、窄补丁、测试和报告；不含原厂完整反编译树、APK、工具或签名密钥。没有自动推送 GitHub。
